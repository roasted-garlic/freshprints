## Goal

Fix Studio release QA gaps discovered after the successful-but-incorrect `studio-release.yml` run for v1.0.2: real lint errors were ignored by a non-fail-fast PowerShell multi-command step, and the draft GitHub Release targeted `development` (`target_commitish`) despite building from production SHA `703f4fc4fe24bc63727710204b03d903a1ca5b5c`.

## Background

- Backend + Portal promote remain live; do not redeploy.
- Existing draft `v1.0.2` must **not** be published until corrective lands and a clean re-run completes.
- electron-builder 24.x `GitHubPublisher.createRelease()` does not send `target_commitish`; GitHub defaults to the repo default branch (`development`).

## Scope

### In Scope
- Remove unused lint symbols in the two reported test files
- Make `studio-release.yml` fail immediately on any failed lint / functions build / portal typecheck / updater unit tests
- After publish, pin the draft release `target_commitish` to the checked-out build SHA (`git rev-parse HEAD`)
- Brief `DEPLOYMENT.md` note for fail-fast + target pin
- development → PR → production

### Out of Scope
- Feature behavior changes
- Firebase / App Hosting / Functions redeploy
- Algolia, DNS, Coming Soon, myprintrequest.com
- Publishing or deleting the existing draft (owner action)
- electron-builder major upgrade for native `targetCommitish` config

## Approach

1. Drop unused `assertFails` import; drop unused `css` read in companion modal test.
2. Split the single "Run tests" step into separate job steps so each command fails the job on non-zero exit (Windows PowerShell does not fail-fast across `npm` invocations in one block).
3. Add a post-build step that locates the draft release for `v${version}` / `${version}` and PATCHes `target_commitish` to `git rev-parse HEAD`.
4. Document the gate + pin behavior in `DEPLOYMENT.md`.
5. Commit on development, PR to production; owner merges and re-runs release.
