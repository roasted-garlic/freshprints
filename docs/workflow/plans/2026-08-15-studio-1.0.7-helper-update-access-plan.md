## Goal

Ship the smallest Studio **1.0.7** hotfix so **Helpers** can use the existing Studio updater (check / download / postpone / restart) **without** `manageSettings` or `/settings` access, by opening the existing `StudioUpdatesSettingsSection` from a sidebar footer action.

---

## Background

Studio 1.0.6 is published. Updater UI lives only under Settings (`StudioUpdatesSettingsSection` on `SettingsPage`), and `/settings` is gated by `manageSettings` (`ProtectedRoute` + sidebar nav item). Helpers are active desktop staff but lack `manageSettings`, so they cannot update Studio through the UI.

Preferred product fix: reuse the existing updater section in a small modal opened from the sidebar footer (near user card / Sign out), available to owner / admin / helper.

---

## Scope

### In Scope

1. Sidebar footer **Studio Updates** control (owner / admin / helper).
2. Small modal hosting existing `StudioUpdatesSettingsSection` as-is (no logic fork).
3. Keep Settings → Studio updates for owner/admin unchanged.
4. Bump Studio version **1.0.6 → 1.0.7** and release finalize pin / signing-policy expectation to **1.0.7**.
5. Focused contract/UI tests + typecheck / lint / Vite build.
6. Docs notes only as needed for version/hotfix (DEPLOYMENT version pin if required by release tooling).

### Out of Scope

- Giving Helpers `manageSettings` or any Settings routes/sections
- Duplicating updater hook/IPC/service logic
- Changing `studioUpdateService`, IPC channels, periodic check behavior
- Firebase / Functions / Rules / Portal / Storage / Algolia
- Mac Developer ID / A2 / notarization / Squirrel changes
- Editing or republishing **v1.0.6**
- Broader Settings redesign or permission model expansion

## Approach

1. **Visibility rule:** Show **Studio Updates** in sidebar footer when authenticated user role is `owner` | `admin` | `helper` (same desktop staff set). Do not add a new permission key unless Review requires it (preferred: no new permission).
2. **Interaction:** Click → open modal → render `<StudioUpdatesSettingsSection />` unchanged → Close dismisses modal. Escape/backdrop close if existing modal pattern supports it.
3. **Settings unchanged:** Keep `StudioUpdatesSettingsSection` on `SettingsPage`; keep `/settings` + nav behind `manageSettings`.
4. **Version:** Bump `apps/studio/package.json` to `1.0.7`; update release workflow finalize pin + signing-policy test string from `1.0.6` → `1.0.7`. Leave Mac `internal-unsigned` / A2-declined policy as-is (wording may still say A2 gated — messaging debt, out of scope unless pin edit touches same line).
5. **Tests:** Contract tests asserting footer action exists for helper without `manageSettings`; Settings nav/route still requires `manageSettings`; modal uses `StudioUpdatesSettingsSection` import/symbol (no duplicated updater API calls in Sidebar).
6. **Release:** After Signoff, separate owner-gated 1.0.7 dispatch from production (not part of this Plan’s Implement).
