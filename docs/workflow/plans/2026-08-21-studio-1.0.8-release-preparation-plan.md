## Goal

Prepare and (after later owner gates) ship Studio **1.0.8** as a stable `internal-unsigned` draft from the production product tree whose merge tip is `97d6d49`. ## Why not dispatch from `97d6d49`

`.github/workflows/studio-release.yml` refuses stable unless `ref` is `production` or a SHA reachable from `origin/production` **and** finalize requires `WIN_VER == 1.0.7` today. `97d6d49` is reachable but still **1.0.7**. Dispatching 1.0.7 from `97d6d49` would collide with the published 1.0.7 updater channel. Owner chose **1.0.8**.

## Approach

1. Formal Review (this pass) → **STOP** before bump.
2. After `APPROVE IMPLEMENT: studio-1.0.8-release-preparation`: edit the three pin files only; run signing-policy test + Studio tsc/lint as in Test Strategy.
3. Commit on `development` (no new branch). Push. Do not push `production`.
4. After create-PR phrase: PR `development` → `production` (version pins + this goal’s docs only).
5. After merge phrase: record new `origin/production` SHA `P`. Confirm `97d6d49` is ancestor of `P`.
6. After dispatch phrase: `workflow_dispatch` `ref=P` (or `production` if tip is `P`), `release_type=stable`, `distribution_mode=internal-unsigned`. Draft only.
7. After dual-platform smoke + publish phrase: owner publishes GitHub Release.
