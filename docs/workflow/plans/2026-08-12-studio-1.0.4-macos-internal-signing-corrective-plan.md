## Goal

Correct the Studio 1.0.4 **internal** Mac distribution strategy so packaged `.app` bundles have a **structurally valid** code signature that passes `codesign -v -vvv --strict --deep`, can be installed on owner Macs, and can be owner-approved through normal macOS internal security flows (unverified → Open Anyway / right-click Open) — **without** Developer ID, notarization, or treating quarantine removal as the product fix.

## Proven root cause (CI artifact evidence)

Inspected the **exact** CI unpacked apps from run `31624159614` (`release-staging/{arm64,x64}/unpacked/Fresh Prints.app`).

### Configuration / CI behavior

| Evidence | Finding |
|----------|---------|
| `apps/studio/electron-builder.json5` | `"identity": null` (production tip) |
| `.github/workflows/studio-release.yml` | `CSC_IDENTITY_AUTO_DISCOVERY=false` |
| Mac job logs | `skipped macOS code signing  reason=identity explicitly is set to null` (arm64 + x64) |
| electron-builder `macPackager.sign()` | When `identity === null`, returns early and **does not** run `@electron/osx-sign` |

### arm64 CI `.app` signature state

| Check | Result |
|-------|--------|
| `Contents/_CodeSignature` | **Absent** |
| `Contents/_CodeSignature/CodeResources` | **Absent** (0 under entire tree) |
| Nested `_CodeSignature` / `CodeResources` | **Absent** |
| Main exe `LC_CODE_SIGNATURE` | **Present** (`blobMagic=0xFADE0CC0`, CodeDirectory present) |
| Helper / Electron Framework / dylibs | Embedded `LC_CODE_SIGNATURE` present |
| Owner Mac `codesign --strict --deep` | Fails: resources required by signature missing |

This matches Apple’s / electron-builder’s known “linker-signed / incomplete signature after post-link mutation” failure mode: binaries claim a signature, but the bundle was never sealed with `CodeResources`. Gatekeeper surfaces this as **damaged**, which cannot be fixed by a supported GUI Open Anyway path — unlike a clean **unverified** ad-hoc or Developer ID signature.

### x64 CI `.app` signature state

| Check | Result |
|-------|--------|
| `Contents/_CodeSignature` / `CodeResources` | **Absent** |
| Main / Helper / Electron Framework `LC_CODE_SIGNATURE` | **Absent** in the uploaded unpacked artifact |
| Conclusion | **Also invalid / incomplete for distribution.** Do **not** ask owner to smoke current x64 DMG before corrective. Treat as same packaging defect class. |

### Why CI previously “passed”

Existing gates only proved arch, sharp load, DMG/ZIP existence, and updater yml merge — **not** `codesign --strict --deep`. That gap is now a required release gate.

## Option evaluation

### Option A — True unsigned (`identity: null` + “cleanup”)

| Pros | Cons |
|------|------|
| Matches prior “unsigned” wording | CI evidence shows `identity: null` **already** skips signing and still leaves arm64 with embedded signatures and **no** CodeResources |
| | Owner failure proves this is **not** a launchable internal distribution state on modern Apple Silicon |
| | Would require a reliable, complete signature **strip** of all nested Electron binaries — not what electron-builder does today when identity is null |

**Reject for Studio 1.0.4 internal Mac.** Option A is what we already shipped; it failed smoke.

### Option B — Ad-hoc signing (`identity: "-"`)

| Pros | Cons |
|------|------|
| electron-builder officially supports ad-hoc via `identity: "-"` (app-builder-lib **≥ 26.0.13**, PR #9007) | Repo currently pins **electron-builder 24.13.3**, which **does not** implement `identity: "-"` (setting it would not correctly ad-hoc sign) |
| Produces sealed `CodeResources` and structurally valid signature | Not Developer ID; Gatekeeper still shows **unverified** (acceptable for internal; has GUI override) |
| No Apple Developer account / cert / notarization | Ad-hoc + default `hardenedRuntime: true` can cause Electron Team ID / library-validation failures unless entitlements are added **or** hardened runtime is disabled |
| Matches industry fix for “app is damaged” on unsigned ARM Electron builds | Mac auto-update via Squirrel.Mac historically expects signed apps; ad-hoc may be insufficient for reliable updates |

**Select Option B**, with least-complex internal settings:

```json5
mac: {
  identity: "-",
  hardenedRuntime: false,
  gatekeeperAssess: false,
  // notarize remains unset/false — no Apple credentials
}
```

**Why preferable:** Fixes the proven structural defect; uses electron-builder’s supported path; avoids Apple credentials; avoids inventing a one-off strip pipeline; converts “damaged” into normal internal “unverified” friction.

**Dependency prerequisite:** Upgrade `electron-builder` (and lockfile-resolved related packages as required by npm) from **24.13.3 → a pinned ≥26.0.13** (prefer latest stable 26.x that CI validates). Justify as required for native ad-hoc identity support. Regression-test **Windows** packaging in the same workflow (do not weaken Windows).

**Entitlements:** None required for the chosen `hardenedRuntime: false` internal path. Future Developer ID + notarization phase will revisit `hardenedRuntime: true` + entitlements (including `com.apple.security.cs.disable-library-validation`) under a separate human checkpoint.

## Updater compatibility finding (audit only — no behavior change in this corrective unless review expands scope)

- Studio uses `electron-updater` → `MacUpdater` / native Squirrel.Mac for apply.
- Electron/macOS auto-update assumes a consistently signed app.
- **Ad-hoc internal builds are not equivalent to Developer ID** for update trust.
- **Plan finding:** Treat **Mac automatic update as unsupported / best-effort** for this internal ad-hoc 1.0.4 path until Developer ID + notarization.
- **Do not** change updater code in this corrective unless Formal Review explicitly expands scope.
- Document the limitation in `DEPLOYMENT.md` + Mac smoke checklist (update check: must not crash; need not successfully install an update).

## Approach

1. Formal Review of this plan (no implement before approval).
2. Branch from current `production` (or agreed base containing Mac dual-arch support) — **separate** from `hotfix/studio-1.0.4-finalize-upload-by-release-id` (PR #65).
3. Upgrade electron-builder to pinned ≥26.0.13; set Mac `identity: "-"`, `hardenedRuntime: false`, `gatekeeperAssess: false`.
4. Add CI verification after each arch’s `.app` is produced:
   - `codesign -v -vvv --strict --deep "<app>"` must exit 0
   - `codesign -d -vvv "<app>"` must show ad-hoc (Authority=adhoc / Signature=adhoc) — fail if Developer ID appears unexpectedly
   - Assert `Contents/_CodeSignature/CodeResources` exists
5. Keep sharp / arch / Big Sur / DMG+ZIP / latest-mac.yml gates.
6. Update signing-policy tests + DEPLOYMENT + Mac smoke checklist (fresh build required; do not smoke old DMGs; do not recommend quarantine clear as the fix).
7. Run validation `studio-release` (prerelease or validation path) — **no GitHub Release mutation** if validation-only guard applies; or owner-authorized draft rebuild later after merge.
8. STOP before publish; prepare owner smoke on **new** Mac artifacts (both arches) + Windows if same-SHA rebuild.
