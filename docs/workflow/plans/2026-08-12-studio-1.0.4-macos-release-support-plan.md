## Goal

Add supported **macOS packaging/release** capability to the existing Fresh Prints Studio release path so the **final** Studio **1.0.4** GitHub Release can contain **Windows + macOS** artifacts built from the **same production SHA**, without forking Studio into a separate Mac app or changing A–E product behavior.

## Background

## Compatibility audit findings (Plan input)

### Already Mac-ready / helpful

| Item | Finding |
|------|---------|
| electron-builder `mac` stanza | Present: `target: ["dmg"]`, `artifactName: "${productName}-Mac-${version}-Installer.${ext}"` |
| Electron main lifecycle | `window-all-closed` keeps app alive on `darwin`; `activate` recreates window — standard Mac pattern |
| Dialogs / FS APIs | Import folder/ZIP, save dialogs use Electron `dialog` (cross-platform) |
| Path safety | Several `process.platform === "win32"` branches in import temp/zip safety — Mac uses POSIX paths |
| Brand assets | `icon.ico`, `icon.png` + `scripts/generate-app-icon.mjs` from approved logo PNG |
| Updater code | `electron-updater` via `studioUpdateService.ts`; channel derived from version (not hardcoded Windows) |
| Prod env bake (production tip) | Stable workflow already fail-closes on `fresh-prints-prod`, Algolia `Z1FVCM5QUX` / `portal_catalog_ready_prod` |

### Incomplete / Windows-oriented

| Item | Finding |
|------|---------|
| CI runner | Single job `windows-latest` only |
| Evidence steps | `*Setup*.exe` SHA-256; `latest*.yml` upload assumes Windows-centric artifacts |
| Signing step | Windows CSC only (`WIN_CSC_*`); `distribution_mode` copy is Windows/SmartScreen oriented |
| Mac arch | Not declared under `mac` (defaults may not match intent) |
| Mac icon | No `.icns`; `mac.icon` unset (builder may synthesize from png — verify in implement) |
| Mac updater target | **DMG only** — electron-updater on macOS typically needs a **ZIP** (or equivalent) + `latest-mac.yml` |
| `npmRebuild: false` | Documented for workspace hoist + sharp; **sharp** must still ship correct **darwin** native binaries when packaging on a Mac runner |
| `asarUnpack` | **Not** configured for `sharp` — risk if native `.node` remains inside asar incorrectly |
| App menu | `Menu.setApplicationMenu(null)` — on macOS removes standard app menu; may block expected Cmd+Q / About behavior for smoke |
| Tests | Signing policy + evidence paths encode Windows assumptions |

### Native dependency risk (`sharp`)

- Only native runtime dependency (`^0.33.5`), externalized in Vite main bundle.
- Packaging must run on **macOS** so `npm ci` resolves **darwin** sharp binaries for the chosen arch.
- Universal binary multiplies sharp packaging complexity; **not recommended for first Mac 1.0.4**.
- Implement must prove packaged Mac app can `import("sharp")` (use existing `ensureSharpLoaded` / derivative verify path).

### Updater implications

| Platform | Metadata | Installer |
|----------|----------|-----------|
| Windows (current) | `latest.yml` (+ blockmap) | NSIS `…-Setup.exe` |
| macOS (needed) | `latest-mac.yml` (electron-builder) | Recommend **dmg** (human install) **+ zip** (auto-update) |

Windows and Mac metadata **can coexist** in one GitHub Release. Do **not** assume `latest.yml` covers Mac.

## Architecture options

### Mac CPU architecture

| Option | Pros | Cons |
|--------|------|------|
| **A. arm64 only** | Matches current `macos-latest` runners; smaller; sharp simpler; most new Macs | Intel Macs unsupported |
| **B. x64 only** | Covers older Intel | Poor match to modern runners/hardware; Rosetta for Apple Silicon users |
| **C. Universal** | One artifact both arches | Larger; sharp dual native; more CI complexity |

**Recommendation:** **A — arm64 first** for internal Studio 1.0.4 Mac, unless owner needs Intel.

**`[NEEDS OWNER DECISION]` — Mac architecture:** confirm **arm64-only** vs also ship **x64** (separate artifact) vs defer Intel.

### Signing / notarization

| Option | Viable for internal 1.0.4? | Notes |
|--------|---------------------------|-------|
| **A. Unsigned internal** | Yes, with Gatekeeper friction | Aligns with Windows `internal-unsigned`; users may need right-click Open / remove quarantine |
| **B. Developer ID signed** | Needs Apple credentials | Future human checkpoint |
| **C. Signed + notarized** | Needs Apple credentials + notarization pipeline | Future human checkpoint |

**Recommendation:** **A — unsigned internal** for first Mac 1.0.4, gated by same `distribution_mode: internal-unsigned` (extend messaging for Gatekeeper). Document that public Mac distribution later requires B/C.

**`[NEEDS OWNER DECISION]` — Accept Gatekeeper friction for internal unsigned Mac 1.0.4?** (Yes recommended.)

### GitHub Actions topology

| Option | Assessment |
|--------|------------|
| A. Single matrix job Windows+Mac | Possible but awkward for OS-specific shells/signing |
| **B. Separate `build-windows` + `build-macos` jobs + `finalize` gate** | **Recommended** — same inputs/SHA; platform-native tooling; fail-closed if either fails |
| C. Separate workflows | Weaker coupling; harder to guarantee same SHA |

**Recommended design (B):**

1. Shared inputs: `ref`, `release_type`, `distribution_mode`.
2. Both jobs checkout **identical** `inputs.ref`; stable guards unchanged.
3. Both bake same Firebase/Algolia fail-closed rules (prefer shared script or duplicated pwsh/bash with parity tests).
4. Windows: existing NSIS + `latest.yml`; Mac: dmg+zip + `latest-mac.yml` on `macos-latest`.
5. Both `--publish always` into the **same draft** for version `1.0.4` (coordinate first publisher / attach assets carefully).
6. `finalize` job: `needs: [build-windows, build-macos]`; pins `target_commitish`; verifies both platform assets + both yml files present; uploads combined evidence. **If either build fails, finalize does not succeed** → not publishable as dual-platform stable.

## Risks

| Risk | Level | Mitigation |
|------|-------|------------|
| sharp fails in packaged Mac | **High** | Build on macOS; unpack/native path fixes; verify load |
| DMG-only breaks Mac auto-update | **High** | Add zip + `latest-mac.yml` |
| Two publish jobs race / corrupt draft | **Med** | Finalize gate; documented attach order; CI proof |
| Unsigned Mac blocked by Gatekeeper | **Med** | Document open steps; later notarization phase |
| Accidental publish of Windows-only draft | **Med** | Publication paused; supersede draft after Mac lands |
| Menu null harms Mac UX smoke | **Low–Med** | Minimal menu restore if needed |

**Overall risk:** **Medium–High** (native + release topology), contained to release engineering.
