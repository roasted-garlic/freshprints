## Proven root causes

### A — Blank queue thumbnails + “Preview Pending”

- Queue uses `design.thumbnailPath`; workspace uses `previewPath ?? thumbnailPath`.
- `DesignThumbnailPanel` shows “Preview Pending” when path empty or `getDownloadURL` fails.
- Fixtures have **null** paths → UI unavailable by contract.
- Secondary: even if paths were written, Storage thumbs/previews **do not exist**.

### B — Automatic AI never starts / eternal “WAITING FOR AI”

Code contract (`975f640` / current Studio source on production tip for Studio files):

1. Background enqueue runs only when `pipelineSuccess === true`.
2. `pipelineSuccess` requires derivative upload + `markDesignDerivativesComplete` with canonical paths.
3. `enqueueAiEnrichment` requires `previewPath || thumbnailPath` or fails precondition.
4. Fixtures: paths empty, `aiProcessingStage=null` → enqueue never reached `queued` (category **1/3**: pipeline never reported success → AI callback never fired / never accepted).

Classification for these fixtures: **import reported catalog success without derivative pipeline success; automatic AI correctly gated off; UI still presents ordinary “WAITING FOR AI”.**

### Import `pipelineSuccess` contradiction

Architecture **allows** `status: "success"` + `importSuccess: true` + `pipelineSuccess: false` when original+doc succeed but derivatives fail (`importOrchestrationService`). Batch UI can still look like a successful import while counting `derivativeFailedCount`. Owner observation of “successful batch” + Processing inbox entries is consistent with **partial success**, not with `pipelineSuccess=true`.

### Windows client vs server Admin Storage

| Path | Evidence |
|------|----------|
| Client `getDownloadURL` | Would fail / Preview Pending given empty paths / missing objects. Packaged builds disable `pipelineLog` and AI queue trace (`app.isPackaged`) — only console.warn/error. No secrets/URLs captured this pass. |
| Server Admin download | Irrelevant until enqueue runs; with empty paths callable would reject. Stage null ⇒ no pipeline attempt recorded. |

Client permission defect is **not** required to explain A or B for these fixtures.

## Approach (implementation — after Formal Review approval)

### Workstream 1 — Fix derivative completion on Studio Windows (primary)

1. Reproduce locally / DEV with large transparent PNGs matching smoke sizes (~7–12 MB).
2. Trace main-process path: `enrichReadResultWithDerivatives` → `derivativeGenerationService` (sharp load/encode) → Storage upload → `markDesignDerivativesComplete`.
3. Fix the failing step (sharp packaging/load, encode, upload, or persist). Do **not** treat “click Start AI” as the product fix.
4. Ensure `pipelineSuccess=true` only when paths **and** objects exist (add verification test).

### Workstream 2 — Failure visibility (A/B UX + state)

1. Persist per-design derivative / AI handoff failure so inbox does **not** look like ordinary “WAITING FOR AI” when derivatives missing or background enqueue fails.
2. Batch import already tracks `derivativeFailedCount` — strengthen UI so partial success cannot be mistaken for full pipeline success.
3. Background queue: on enqueue failure, reconcilable per-design error (not only console); evaluate `seenDesignIds` session dedupe so failed auto-enqueue is not permanently blocked without a clear recovery path.
4. Optional: if paths missing, Processing badge/label distinct from waiting-for-AI.

### Workstream 3 — Cleanup

**OPTION A — One-time owner-authorized cleanup** of the **exact** 8 fixture IDs after corrective evidence + DEV cleanup verification.

**OPTION B — Permanent owner-only Studio workflow** to fully delete eligible unapproved designs (doc + originals/thumbnails/previews).

**Recommendation:** Implement **both**:

- **B** as the product gap fix (Studio production-safe for future smoke).
- **A** as the authorized production incident cleanup using B’s callable (or a one-shot Admin script that shares B’s fail-closed guards) on the exact ID allowlist.

#### Fail-closed delete contract (B)

| Guard | Rule |
|-------|------|
| Actor | Owner only |
| Status allowlist | Explicit: e.g. `imported` (+ maybe `processing` if stuck); **deny** `ready` and unknown future statuses |
| AI | Allow pending / failed / never-started; deny if actively mid-pipeline unless stale policy defined |
| References | Deny if print-request items, show allocations, production allocations, companion-set links, `sourceCustomerUpload` / promoted upload provenance, or other repo-proven refs |
| Storage | Delete original + thumbnail + preview (canonical paths) |
| Firestore | Delete design document after Storage success (or compensating retry); define partial-failure recovery |
| Sequencing | Prefer Storage delete then Firestore delete with idempotent retry; never leave ready designs orphaned into public |
| Bulk | Bounded size; destructive confirmation + exact phrase |
| Not | General wipe / Test Data Reset expansion without separate auth |

Incident sequence (future — **not** this Plan/Review pass): evidence → plan approve → implement/test → DEV verify cleanup → owner auth exact IDs → revalidate → delete → verify → record.

### Workstream 4 — Release

1. Keep `369614747` draft unpublished / untouched (failed-smoke evidence).
2. After corrective merges to production lineage: **new** dual-platform 1.0.4 draft (version may stay 1.0.4 — never published).
3. Fresh smoke: Windows + Mac arm64 + Mac x64 Big Sur on **same** new build only.
