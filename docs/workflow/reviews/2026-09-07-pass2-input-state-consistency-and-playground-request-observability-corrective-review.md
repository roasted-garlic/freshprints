## Review of proposed corrective architecture

The explicit four-part `pass2Diagnostics` projection is the right narrow
boundary:

1. `semanticReviewInput` captures the exact eligibility inputs and blocker
   state.
2. `renderedPrompt` captures the exact system and rendered user messages.
3. `providerRequest` captures the safe request body and complete response
   contract immediately before dispatch.
4. `patchValidationInput` captures raw, parsed, canonical, and validation
   state at the validator boundary.

This is preferable to turning on full raw trace capture because it retains
diagnostic meaning while excluding authorization, credentials, image bytes,
and unbounded payloads. Explicit schema projection is necessary because
generic recursive key/depth scrubbing can erase enums, required fields,
properties, array items, and request options. The projection must display
truncation markers rather than silently presenting incomplete values.

The existing fail-soft trace-store behavior should remain unchanged. A trace
write failure must not affect enrichment, and ordinary unit tests must be able
to use an in-memory sink without Firestore. No trace-only AI call is allowed.
