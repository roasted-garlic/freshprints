# Workstream C

## C1. Source discriminator — pass

Expanding `UpcomingShowSource` to `"whatnot" | "staff_gang_sheet"` is the smallest clean discriminator. It matches the existing field (`source`), Rules validator `isValidUpcomingShowSource`, and Whatnot upsert identity. Do **not** add a parallel `kind` field.

Branch all Staff-specific behavior on `source === "staff_gang_sheet"` only. Whatnot path remains `source === "whatnot"`.

## C2. whatnotShowId decision — **A: source-conditional optional**

| Option | Verdict |
|--------|---------|
| **A. Source-conditional optional `whatnotShowId`** | **APPROVED (required change)** |
| B. Synthetic internal `whatnotShowId` | **Rejected as preferred** |

**Rationale:** Owner preference against fake Whatnot semantics is correct. Repo evidence shows the non-empty `whatnotShowId` requirement is only in Rules (`upcomingShowRequiredFieldsValid`) + TypeScript shape + Whatnot upsert — not a fundamental storage invariant for non-Whatnot batches. Narrow branching:

- `source === "whatnot"` → `whatnotShowId` required, immutable, validated as today
- `source === "staff_gang_sheet"` → field **absent / omitted** (not empty string; not synthetic)

Update: shared type (`whatnotShowId?: string` with source-conditioned validation), Rules, `mapUpcomingShowData` / upsert paths (Whatnot-only), import (unchanged), tests.

Synthetic IDs are **not** approved unless implement proves optional branching is unsafe — Review finds no such evidence; optional is less complex than carrying forever-fake Whatnot identity.

| `source: "staff_gang_sheet"` | Yes |
| `assignedStaffUserId: string` | Yes |

| Extra unlimited boolean / sentinel capacity | **No** |
| Parallel collections | **No** |

Reuse existing production/timer/allocation/audit fields unchanged. Omit `maxTotalQuantity` for Staff cycles.

## C4. Unlimited capacity — pass

Confirmed: `assessShowCapacity` treats `maxTotalQuantity === undefined` as unlimited. Staff cycles must omit the field.

**Required implement audit (binding):** Walk Studio/Portal capacity consumers (`showAllocationEligibility`, `AddToShowModal`, `UpcomingShowsPage` capacity chrome, `planAllocationSplit`, Portal fit helpers) and ensure Staff paths never surface Full / 0 remaining / override / forced split. Whatnot unchanged.

## C5. Allocation reuse — pass

`showAllocations` remains authoritative. No parallel allocation collection. Print Request production state stays allocation-driven. Designs never gain queued/printed lifecycle.

## C6. Request-origin eligibility — binding recommendation

Repo: `studio_customer` = **“Staff Created”** (Studio-authored customer-named requests); `portal_customer` = **“Customer Submitted”** (Portal).

| Origin | Decision |
|--------|----------|
| `studio_internal` | **ALLOW** |
| `studio_customer` | **ALLOW** — staff-controlled; matches helper “own/internal production” work that is customer-named without Portal queue submission |
| `portal_customer` | **DENY** — would pull customer Portal queue/progress into internal Staff batches |

Do not invent a new origin. Portal callables must still reject Staff show IDs even for allowed Studio origins.

## C7. Permissions — pass with changes

| Actor | Access |
|-------|--------|
| Owner/admin | All Staff lanes: create/assign, add/remove, export, complete, history |
| Assigned helper | Own `assignedStaffUserId` lane only |
| Other helper | No cross-lane manage |
| Portal customer | None |

Create/assign lanes: **owner/admin only** — approved.

**Binding change:** Assignment checks must be enforced in **Firestore Rules** (and/or a trusted callable), not only `permissionService` UI. Today staff have broad `upcomingShows` write; without Rules branching, a helper could mutate another lane via client SDK.

## C8. Portal isolation — pass (mandatory)

Plan’s defense-in-depth is approved:

- `listPortalAllocatableShows` — exclude `staff_gang_sheet`
- `queuePortalPrintRequestToShow` — reject Staff IDs
- Portal calendar / progress / schedule readers — never treat Staff as customer shows
- Rules — customers still cannot client-read `upcomingShows`
- UI filtering alone — **insufficient**; callable reject required

## C9. Recently Requested — pass

Skip design popularity / `showAddCount` bumps when parent show `source === "staff_gang_sheet"` in `onShowAllocationCreated`. Must not block unrelated allocation lifecycle (upload intake transition remains a separate Review note — default: do not invent new upload behavior for Staff; prefer catalog-oriented Staff work; if upload allocations occur, document side effects in implement notes without expanding Portal visibility).

## C10. Completion + auto-cycle — pass with changes

Approved invariants: complete N → create open N+1; history preserved; one open cycle per lane; idempotent under double-click/retry/concurrency.

**Preferred architecture:** `upcomingShowService` **Firestore transaction** (no unguarded React `addDoc`).

**New callable:** **Not required by default.** Introduce a callable only if Rules cannot safely express helper-limited create/update for Staff cycles. Prefer Rules + service TX.

## C11. Indexes — minimal approval

Studio today loads `upcomingShows` via **full-collection** `listUpcomingShows` + client sort. Staff tab history can filter that list client-side → **no speculative history index**.

**Approved index (only if implement uses this query inside complete+next TX / uniqueness assert):**

```
Collection: upcomingShows
Composite:
  source ASC
  assignedStaffUserId ASC
  productionStatus ASC
```

Query shape:

```
where("source", "==", "staff_gang_sheet")
where("assignedStaffUserId", "==", <uid>)
where("productionStatus", "==", "open")
```

Do **not** add further composites unless implement introduces a real additional query.

## C12. UI reuse — pass

Reuse `UpcomingShowsPage` with Shows | Staff Gang Sheets separation and conditional chrome (hide Whatnot URL/ID/schedule-as-needed, capacity, full, override, split messaging). Do not fork a second Show Queue shell.

## C13. Export reuse — pass

Existing ZIP / gang-sheet exporters consume allocations by `upcomingShowId` — reuse unchanged. Label/filename branches only if they assume Whatnot metadata.
