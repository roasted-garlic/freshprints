## Architecture Review

**Findings:**
- Dual-job + finalize topology is appropriate; avoids cross-compiling Mac on Windows.
- Keeping shared app logic unified is correct.
- `Menu.setApplicationMenu(null)` is a real Mac UX risk; allow minimal fix only if smoke requires it.

**Required changes:**
1. Implement must **not** treat optional menu fix as a UI redesign license.
2. First Mac package attempt must explicitly validate **sharp** load in packaged output before claiming success.

---

## Security Review

**Findings:**
- Reusing stable Firebase/Algolia fail-closed gates on Mac job is mandatory.
- Unsigned Mac for internal use is acceptable **only** with Gatekeeper docs and `internal-unsigned` gating.
- No Apple credential work in this phase (correct).

**Required changes:**
3. Mac job must refuse stable builds that embed `fresh-prints-dev` or `portal_catalog_ready_dev` (parity with Windows).

---

## Testing Review

**Findings:**
- Automated Windows retention + Mac CI package + metadata coexistence are covered.
- Manual Mac smoke list matches owner requirements.

**Required changes:**
4. Finalize job (or equivalent) must **fail** if either Windows or Mac required assets/`latest.yml`/`latest-mac.yml` are missing — no silently publishable half-release.

---

## Required Changes (binding for Implement)

1. **Owner decisions recorded before coding:**
   - Mac arch: default implement **arm64-only** unless owner selects otherwise.
   - Signing: default implement **unsigned internal** unless owner requires wait-for-Apple.
2. Add **zip** Mac target for updater (do not ship DMG-only as “updater complete”).
3. **Supersede** Windows-only draft `369361779` after Mac-support merge + dual rebuild; do not publish it as final 1.0.4.
4. Do not mutate draft `369361779` during implement until Mac-support is merged and dual rebuild is intentional.
5. Extend workflow tests beyond Windows signing-only assumptions.
6. Publication remains a **separate** owner checkpoint after **both** platform smokes.
