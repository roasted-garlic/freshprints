Date: 2026-08-02

## Verdict: PASS — ready for production promotion subject to production release gates

Studio automatic updates are fully implemented, unit-tested, and **live-proven end to end** across
four consecutive real update cycles on a real installed application. This Signoff does **not**
claim stable `1.0.0` has been published or that production Studio has been updated — those remain
separate, later, explicitly human-gated steps (see the production convergence audit,
`docs/workflow/reviews/2026-08-02-production-convergence-audit.md`).

## Summary of verified behavior

| Area | Behavior | Evidence |
|---|---|---|
| Packaged build-time channel selection | Compiled-in constant (`apps/studio/electron/generated/packagedBuildConfig.ts`, gitignored, generated by `apps/studio/scripts/generate-packaged-build-config.mjs` from a build-time-only env var) — never a runtime environment variable, which an installed app never has | Live-proven: beta.2 through beta.5 all self-reported the correct channel after install |
| Stable/prerelease isolation | `allowPrerelease` gated on the packaged channel; `updater.channel` deliberately left unset so electron-updater derives it from the version's own semver prerelease tag, matching exactly what electron-builder publishes (`beta.yml` for `1.0.0-beta.N`, never a `latest.yml`/`prerelease.yml` mismatch) | Fixed after the original HTTP 406 root-cause; live-proven across 3 subsequent detections |
| GitHub Release feed behavior | Publishes to GitHub Releases on the confirmed-public `roasted-garlic/freshprints` repo — no embedded credential | `electron-builder.json5`'s `publish` block; live-proven |
| User-approved download | `autoDownload = false`; download only starts on explicit "Download update" click | `studioUpdateService.ts`; live-proven |
| User-approved Restart to Update | Install only triggered by explicit renderer IPC call, gated on `canRestartAndInstall` + a pending-downloaded-update flag | `studioUpdateService.ts`; live-proven |
| Silent automatic install | `quitAndInstall(true, true)` — no NSIS wizard for the automatic-update path | Live-proven twice (beta.3→4, beta.4→5) after the original wizard-appearing defect was fixed |
| Automatic relaunch | `isForceRunAfter=true` | Live-proven every cycle |
| Safe updater error mapping | `toSafeStudioUpdateError()` converts any raw error (which can carry full HTTP bodies/headers/cookies/stack traces per electron-updater's own source) to one of 5 fixed, pre-written messages based only on structural signals | Fixed after the original raw-406-response defect; no raw error observed in any subsequent cycle |
| Safe bounded release-note rendering | `normalizeStudioReleaseNotes()` converts GitHub's rendered HTML to plain text (strips script/style content, converts block elements to line breaks, extracts anchor text, decodes entities, caps at 2000 chars); rendered in a CSS-bounded, scrollable, non-`<pre>` container | Live-proven with a release body containing headings, bold text, lists, a link, and a long unbroken string — all rendered safely and boundedly |
| Preserved login/settings/data | Sign-in, Settings, and `fresh-prints-dev` data all survive an update | Live-proven across 4 consecutive updates |
| Development Firebase isolation | Packaged builds embed `VITE_FIREBASE_PROJECT_ID` from `DEV_FIREBASE_*`/`PROD_FIREBASE_*` GitHub secrets selected by `release_type`; confirmed zero `fresh-prints-prod` strings in every prerelease bundle inspected | Verified via direct `app.asar` extraction on every beta build (beta.2 through beta.5) |
| CI release workflow | `.github/workflows/studio-release.yml` — manual `workflow_dispatch` only, `ref` + `release_type` inputs, stable restricted to `production`-reachable refs, installs both dependency trees, runs the full test/lint/typecheck gate, generates the packaged config, configures Firebase env and signing conditionally, builds and publishes | Iteratively fixed across 5 CI-specific remediation passes (Functions dependency install, optional signing, dev Firebase config, generated-config step ordering, hardcoded test value) — all merged to `development` |
| Manual prerelease publish checkpoint | electron-builder's GitHub publisher creates every release as a **draft**; it does not reliably auto-check "Set as a pre-release" — confirmed against the real beta.2 publish attempt. Marking prerelease and publishing are both manual GitHub UI actions for every release this workflow produces | Documented in `docs/standards/DEPLOYMENT.md`'s "Human approval gate before any release is publicly visible" (corrected 2026-08-02 after the discrepancy was observed) |
| Stable release signing requirement | The `Configure optional Windows signing` workflow step fails closed (before packaging) for `release_type: stable` if `WINDOWS_CSC_LINK`/`WINDOWS_CSC_KEY_PASSWORD` secrets are not both set — no unsigned stable release can be produced without an explicit, separately reviewed exception | `.github/workflows/studio-release.yml`; not yet exercised for a stable build (no stable build has been produced) |

## What this Signoff does NOT claim

- Stable `1.0.0` has not been built, signed, or published.
- Production Studio has not been updated.
- No production Firebase resource has been deployed as part of the updater feature.
- Windows code signing is not yet configured (`WINDOWS_CSC_LINK`/`WINDOWS_CSC_KEY_PASSWORD` secret
  status is owner-only information, not verifiable from this environment).
