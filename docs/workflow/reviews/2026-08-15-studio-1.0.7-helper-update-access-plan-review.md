## Architecture Review

**Findings:** Sidebar → settings feature component is acceptable for this hotfix. Prefer a thin `StudioUpdatesModal` (overlay + close + section) over inlining overlay markup in `Sidebar.tsx`. Existing pattern: `modal-overlay modal-overlay-blur` + `Modal` / `role="dialog"`.

**Required changes:**
- [x] Visibility: use `permissionService.canAccessDesktopApp(user)` (existing desktop roles). **Do not** add a new `PermissionKey`.
- [x] Prefer **zero** edits to `StudioUpdatesSettingsSection.tsx` (wrap/style in modal only).

---

## Security Review

**Findings:** Exposing updater to Helpers who already run packaged Studio is appropriate. Risk is accidental Settings exposure — mitigated by not touching `manageSettings` gates.

**Required changes:**
- [x] Do not change `AppRoutes` `/settings` `ProtectedRoute`.
- [x] Do not change Settings sidebar nav `permission: "manageSettings"`.

**Human approval needed before production:**
